# 值班排障顺序

目标是「用最少的查询拿到能过门禁的双源证据」，不是把所有工具都试一遍。

## 顺序（前一步有结论就不要往下跑）

1. **知识库**：用现象原话检索（不要自己先归纳成类名）。看命中条目的
   `root_cause_class` 和 `standard_action`——这是处置方法的唯一权威来源。
2. **历史工单**：拿第 1 步的类名查同类事件，对照本次现象是否同一形状。
   这一步是「第二来源」，不做它就只能给单源结论，会被门禁退回。
3. **系统结构**：只在结论涉及「哪个组件/影响面」时才查，用来把处置动作
   落到具体组件上；不构成独立证据。

## 什么算证据

- 必须是工具返回的**原文片段**（10~40 字），能脱离上下文看懂；
- 一条证据只支撑一个断言；「大概是配置问题」不是证据，是猜测。

## 什么时候必须停

- 知识库 `enough=false` → 直接 unknown + 转人工，**不许编类名**；
- 现象涉及重启/删除/清空/改配置 → 停，交人工审批，不要自己执行；
- 两个来源指向不同类目 → 不要投票选一个，如实说明冲突并转人工。
