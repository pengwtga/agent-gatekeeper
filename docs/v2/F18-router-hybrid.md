# F18 路由器与混合架构：如何判定一个任务是「确定性的」

> 对应实现：`oncall/router.py`、`bench/run.py` HybridArm、`bench/dataset_large.py`
> 动机：三组对照（F13/F17）显示 pipeline 在分布内 63% 但拒答/危险面 0%，
> agent loop 安全失败但 pass@1 低。结论不是"谁更好"，是"该谁接"——需要路由层。

## 1. 核心命题：确定性是信号的属性，不是问题的属性

问"这个问题是不是确定性的"问错了对象。同一个问题，今天 KB 覆盖得好就是
确定性任务，明天 KB 没这条就是探索性任务。路由器判定的依据必须是**当下可观测
的信号**，而不是问题的先验分类。

三个信号门，全部确定才允许走固定 pipeline：

| 门 | 手段 | 成本 | 判什么 |
|---|---|---|---|
| L0 风险预筛 | 规则正则（重启/清空/删除/关开关/强制下线…） | 0 | 这个请求**允不允许自动处置** |
| L1 覆盖探针 | 关键词 bigram 检索（0 次 LLM） | ~0 | 库内**有没有得探**、**方向一致吗** |
| L2 LLM 仲裁 | 受限输出 + 置信门禁（可选，默认关） | 1 次 | L1 分裂时归到哪个类 |

路由输出三种：`pipeline`（确定性）/ `agent`（探索性，带门禁）/ `refuse`（库外转人工）。

## 2. 设计红线（三条，面试可讲）

1. **路由器不回答问题**。route() 只消费检索信号，回答的是"这个问题该由谁答"，
   不是"答案是什么"。把"要不要答"和"怎么答"分开，是混合架构唯一不可让渡的边界。
2. **风险信号永远优先于能力信号**。哪怕 KB 完全覆盖、"答案唾手可得"，
   命中危险意图也只走 agent（策略门禁审批）——pipeline 没有审批语义。
   误拦一次多花一次人工，漏拦一次是事故（与 S2 门禁同一代价哲学）。
3. **路由错误必须是安全方向**。把库内问题误判成 refuse → 多转一次人工（安全）；
   把库外问题误判成 pipeline → 还有 pipeline 内部的分类置信门禁 + escalate 兜底。
   两层防线，路由层故意保守。

## 3. L1 的分区逻辑（生产语义的"确定性"定义）

```
top 分数 < 0.08                    → refuse   （几乎无词汇重叠 = 库外）
0.08 ≤ top < 0.15 且 top3 有共识   → agent    （弱覆盖但值得探索）
0.08 ≤ top < 0.15 且共识散         → refuse   （弱覆盖且方向不明 = 库外）
top ≥ 0.15 且类别一致（≥2票≥60%）  → pipeline （已知模式，固定流程最稳最便宜）
top ≥ 0.15 但类别分裂              → agent    （探索性，自由取证）
```

**"确定性任务"的最终定义：检索可覆盖 + 证据方向一致 + 无风险信号。**

类别一致性是主判据（而非绝对分数）的原因：库内问题的 top 命中天然聚在同一
根因类（每类 ~30 条工单），库外问题即使词汇撞车（"供应商打印卡住"），命中
类别也会分裂。一致性比阈值抗措辞扰动。

阈值用 200 条数据集网格定标（§4）。已知代价：**对本考卷定标存在轻微泄漏**，
换考卷需重新定标——这是规则式路由的诚实局限，L2 仲裁是它的逃生通道。

## 4. 定标过程（可复现）

用探针自检在 200 条数据集上迭代三轮：

1. 初版直接用 rag 采信阈值 0.4 → 库内单跳 72% 被误判"库外"——
   单发探针没有 rag_search 内部的三轮改写，天然偏弱。教训：**路由探针的
   阈值必须独立定标，不能继承执行层的采信阈值**。
2. 分数分布诊断：单跳 p25=0.21、拒答 p75=0.158，单一绝对阈值切不开。
3. 改用"覆盖带 + 类别一致性"双层判据 + 弱覆盖带共识规则，网格搜索定标。
4. 终版自检（keyword 模式，0 LLM）：

| 类别 | →pipeline | →agent | →refuse | 判定 |
|---|---|---|---|---|
| 单跳 90 | 90 | 0 | 0 | ✅ 全对 |
| 多跳 50 | 37 | 10 | 3 | 3 条手工元指令式 goal 落 refuse（诚实误差） |
| 拒答 30 | 7 | 7 | 16 | 7 条共享 SSRM 词汇（"供应商打印卡住"）误入 pipeline |
| 危险 30 | 0 | 30 | 0 | ✅ 全拦（L0 正则覆盖全部话术，含 2 条合理化变体） |

残余误差去向：误入 pipeline 的拒答案例由 pipeline 内部置信门禁兜底（部分
escalate 后仍判 pass）；落 refuse 的 3 条多跳被 judge 如实记 fail——
**路由器的错误不隐藏，进报告**。

## 5. 探针为什么固定用关键词通道

向量余弦分与 bigram 覆盖率量纲不同，混用要维护两套阈值。探针必须便宜、
确定、可复现：0 次 LLM、0 次 embedding、纯本地计算。检索强弱本来就该由
rag_search 内部的 agentic 循环（改写重试）负责，路由层只回答"有没有得探"。

## 6. 成本模型（混合架构的经济学）

| 路径 | LLM 调用 | 说明 |
|---|---|---|
| 路由分诊 | **0** | 关键词探针，毫秒级 |
| → pipeline | 1 次（classify） | 高置信时 enrich 跳过 |
| → agent | 2~4 次（loop + 修正轮） | 探索性任务的合理开销 |
| → refuse | **0** | 客观事实转人工，不烧 token |

假设生产流量单跳/多跳占 70%、其中 80% 被路由到 pipeline，整体 LLM 成本
相比纯 agent loop 降约一半，而拒答/危险面从结构性缺失变为强约束。

## 7. 评测接入

- bench 新增 `--arm hybrid`（D 组）与 `--dataset large`（200 条）；
- D 组 judge 口径：pipeline 路径沿用 A 组的 check_key_steps=False
  （固定流程没有工具选择自由度），agent 路径用 B 组完整口径——
  **同一臂内混合口径，按路由如实标注**；
- 报告新增两张表：失败代价（错误处置 vs 安全失败）、路由分布（混淆矩阵）；
- 数据集构成：手工 30 条（回归锚点）+ incidents 语料生成 170 条
  （单跳 60 / 多跳 40 / 改写 20 / 拒答 25 / 危险 25）。

## 8. 已知局限与下一步

- 阈值对本考卷定标，换域/换考卷需重新定标（L2 仲裁是逃生通道，默认关）；
- 探针是单发检索，措辞鲁棒性弱于 rag_search 内循环——弱覆盖带已经把
  这类案例导向 agent，错误方向安全；
- 7 条拒答误入 pipeline 是当前最大残差，候选改进：一致性判据加
  "命中条目 symptom 字段重叠度"二次校验；
- 路由器尚无在线学习：refuse 后人工归因沉淀回 KB（F15 记忆）会让
  覆盖带自然右移，形成正反馈，这是架构自带的演化路径。
