# 事故复盘写法

复盘的目标是让**没参与的人**能照着重演一次，不是写检讨。

## 必含六段

1. **时间线**：发现 → 定位 → 恢复 → 验证，每段带时间戳和当时看到的现象；
2. **影响面**：受影响的功能、供应商、时长；用数据不用形容词；
3. **根因**：一句能过门禁的话（现象 + 机制），不是「配置有问题」这种同义反复；
4. **处置动作**：实际做了什么、为什么是这个而不是别的；
5. **校验项**：怎么确认恢复了（哪条指标/哪类工单回到正常），**不可省**；
6. **待办**：每条带负责人和截止时间，**不可省**；没有待办的复盘等于没复盘。

## 不可省的三项

- 时间戳（「大概上午」不算）；
- 校验项（「应该好了」不算）；
- 待办（「后续关注」不算）。

## 不许写

- 归因到「人为失误」却不写机制——人的操作出错，说明系统缺防护；
- 把「加强监控 / 提高意识」当待办——不可验证的待办等于没写。
