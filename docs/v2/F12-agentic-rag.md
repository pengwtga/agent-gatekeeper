# F12 Agentic RAG（检索助手升级）

迭代：I3 ｜ 依赖：F02 F04 ｜ 代码：`oncall/rag_loop.py`（或并入 `app/agents/rag_assistant.py` 的新模式）

## 1. 目标

把检索助手从「一次检索 + 一次生成」升级成「检索 → 自评 → 改写 → 再检索」，**只在证据不足时才多跑一轮**。

## 2. 为什么这条值得 agent 化（与根因分类做对照）

| | 根因分类 | 检索助手 |
|---|---|---|
| 决策数 | 单次 | 多次（每次检索后都要判「够不够」） |
| 不确定性来源 | 输入已结构化，类别固定 | **用户措辞与 KB 措辞不一致**，是真实的不确定性 |
| 有环的收益 | 0（重跑一遍还是那个答案） | 高（换个说法往往就能召回） |
| 结论 | **保持 workflow** | **值得加一个小 loop** |

这张表是 README §2 的具体化，也是面试里「你为什么不全做成 agent」的正面回答。

## 3. 循环设计（上限 3 轮）

```
q0 = 用户问题
for i in 1..3:
    hits = retrieve(qi, mode=hybrid|keyword+rerank)     # v1 已有两种检索
    if enough(hits):  break                              # 证据字段 ≥2 且分数 ≥ 阈值
    qi+1 = rewrite(qi, hits, reasons)                    # 见 §4
generate(answer, hits)
```

**enough() 的判据**（与 F07 同口径，避免两套标准）：
- top1 分数 ≥ 域阈值（ssrm 0.4 / csa 0.3 / credit 0.2，v1 已定标）
- 且命中条目覆盖 ≥2 个不同字段（现象 / 动作 / 根因）

**预算**：每轮从 `Budget` 切 8s；总轮数 3；第 2 轮起禁用 LLM 重排（贵且收益递减），改走关键词。

## 4. 改写策略（不引入新组件）

| 现象 | 改写动作 |
|---|---|
| 召回为空 | 删掉内部单号/时间戳等噪声词；保留现象词 |
| 召回到了别簇 | 用同簇母本的 `title` 做 query 扩展（KB 是 30 簇 × 5，母本措辞最标准） |
| 分数低但同簇 | 换成母本的 `symptom` 关键词再检一次（等价于「用标准说法重问」） |
| 两轮都不行 | 停止，返回「未覆盖」+ 最接近的 3 条，**不硬答** |

**为什么不引入向量库/新检索器**：问题不在召回器不够强，在**用户说法与 KB 说法不一致**。改写是针对性解法；换更强的检索器是碰运气，且会让评测不可比。

## 5. 与 v1 的两条互斥路径的关系

v1 的 `_retrieve` 按 mode 分叉：`hybrid`（向量∥关键词 → RRF → 截 3，**不调 LLM**）与 `keyword+rerank`（宽召回 8 → LLM 重排 → 取 3）。v2 不改这个分叉，只在**外层**加循环：

```
agentic loop（v2 新增）
   └─ 每轮调一次 _retrieve(mode=...)   ← v1 原样不动
```

**这点必须讲清**：v2 的循环不是「RRF 之后接重排」那种串行错误（v1 文档里已经纠正过一次），RRF 与重排仍然是**互斥**的。

## 6. 输出契约

```json
{"answer": "...", "evidence": [{"field": "symptom", "ref": "ONCALL-042", "quote": "..."}],
 "rounds": 2, "rewrites": ["删掉单号 XF-885", "用母本措辞重检"], "confidence": 0.62}
```

`rewrites` 必须落库：它是调优的唯一线索（哪类改写有用、哪类白跑）。

## 7. 取舍

- **不做 query 分解（multi-query 并行）**：本项目问题多为单点，分解收益低、token 翻倍。
- **不做答案级自我批判**：证据门禁已经覆盖「无证据」这一主要失败模式。
- **不做多轮对话历史**（T5-04 的改写式多轮是独立话题，别混进来）。

## 8. 验收

1. 多跳集（10 条，v1 首轮必失败）：v2 pass 从【待实测】到【待实测】
2. 平均轮数 ≤ 1.6（说明只在需要时多跑，没有无脑跑满 3 轮）
3. 库外问题（10 条）：**必须拒答**，不允许「最接近的 3 条拼一个答案」
4. 成本：p95 延迟增幅 ≤【待实测】%（多一轮的代价要写出来）

## 9. 面试一句话

「检索值得 agent 化，因为失败原因是『说法不一样』，多问一次就能修正；分类不值得，因为重跑一遍还是同一个答案。判断标准不是任务重要不重要，是有没有新的信息能被下一轮用上。」
