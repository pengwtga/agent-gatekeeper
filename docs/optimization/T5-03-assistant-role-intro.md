# T5-3 助手的人设没进 prompt（默认值吃掉配置）

## 1. 问题

三个领域共用同一个助手引擎，人设由 `AssistantSpec.role_intro` 声明。但 ssrm 的 pack
漏传了这个字段，而引擎里是这么用的：

```python
system_prompt = self._answer_prompt.render(
    role_intro=spec.role_intro or "智能助手", id_field=id_f)
```

`or` 让「没配」和「配了空串」都静默退化成「智能助手」，于是 ssrm 的 system prompt 首句是：

```
你是智能助手。用户遇到问题时会来问你。
```

后果不是报错，而是**约束悄悄消失**：csa 的「不当评判商家」、credit 的「合规红线」、
ssrm 的「只给基于历史工单的建议、不臆造系统操作」这些原本该写在 system prompt 里的人设边界，
一个都没进去；实际只剩知识库条目的 `resolution` 文本在兜。

这类 bug 特别难发现：接口 200、答案看起来也正常，只有把 prompt 打出来才看得见。

## 2. 判断

两件事要分开处理：

1. **配置缺失必须可见**。领域包的字段有语义（人设即约束），不能靠引擎的兜底值掩盖。
   兜底值只该兜「引擎单独被用」的场景（测试、`AssistantSpec()` 默认构造），
   不该兜「领域包声明漏了」的场景。
2. **兜底句式本身也是错的**。模板 v1 是「你是{role_intro}。用户遇到问题时会来问你。」，
   而三个领域的 `role_intro` 都以「……会来问你」结尾，拼出来每个 system prompt 都重复一遍：

   ```
   你是电商客服团队的坐席助手。客服坐席在接待用户咨询/投诉时会来问你。用户遇到问题时会来问你。
   ```

   这是「模板和变量各自都通顺、拼起来重复」的典型。

## 3. 方案取舍

| 方案 | 取舍 |
|---|---|
| ✅ 补 ssrm 的 `role_intro` + 加单测 | 直接补缺失；单测守住「三域都不为空」这条不变式 |
| ✅ 模板升 v2，首句只留「你是{role_intro}。」 | 人设与场景全部由领域包给出；v1 保留可逐字回滚（T3-1 的版本机制正好用上） |
| ❌ 把 `or "智能助手"` 删掉 | 会让「引擎单独使用」的路径拿到空串，prompt 变成「你是。」 |
| ❌ 只改模板不补 ssrm 的字段 | 修了重复，仍然是人设缺失 |

## 4. 改动

| 文件 | 改动 |
|---|---|
| `app/domains/ssrm/__init__.py` | 补 `role_intro="SSRM（供应商管理系统）值班团队的运维助手，值班同学遇到注册/变更卡单、EA 同步失败、审批回调异常时会来问你"` |
| `app/agents/rag_assistant.py` | `_default_spec()` 同样补 `role_intro`（`spec=None` 的构造路径也会退化） |
| `prompts/rag_answer.v2.md` + `index.json` | 首句改为「你是{role_intro}。」，`active=v2`，`note` 写明去冗余的原因 |
| `tests/test_domain_packs.py`（新增 9 例） | 三域 `role_intro` 非空且不含「智能助手」；`pack.role_intro ≠ assistant.role_intro`；渲染后首句「会来问你」最多出现一次 |

`pack.role_intro` 和 `assistant.role_intro` 是**两个不同语义的字段**，单测里显式断言它们不相等：

- `pack.role_intro`：分类器的系统拓扑知识（xFlow / EA / Dora 各是什么、怎么交互）
- `assistant.role_intro`：助手的人设与边界（谁在什么场景下来问、不该做什么）

之前 ssrm 只有一个（拓扑那份），助手拿不到人设；现在两份都有，且语义分开。

## 5. 验收

三域 system prompt 首句（实跑渲染）：

```
ssrm   你是SSRM（供应商管理系统）值班团队的运维助手，值班同学遇到注册/变更卡单、EA 同步失败、审批回调异常时会来问你。
csa    你是电商客服团队的坐席助手。客服坐席在接待用户咨询/投诉时会来问你。
credit 你是消费信贷催收团队的催员辅助助手。催收专员与债务人沟通前/中会来问你。
```

`/health` 的 `prompts` 显示 `rag_answer: v2`；启动时的占位符校验通过（v2 的 `vars` 与文本一致）。
全量 75 → 84 passed（+9），ruff 通过。

## 6. 边界

1. **兜底值仍然存在**。`or "智能助手"` 保留着，用于引擎被单独实例化的场景；靠单测守住
   「领域包不许漏」，而不是靠删兜底。
2. **人设只是软约束**。它写在 system prompt 里，模型仍可能违反；硬约束要靠工具层白名单
   和证据门禁（T5-0）。这里修的是「该说的话没说」，不是「说了就一定守」。
3. **prompt 改动没有重新评测**。`rag_answer` 不参与分类回归集（T3-1 的 20 条是分类的），
   所以 v1→v2 没有量化对比；它只改了首句冗余，不动规则部分。

## 7. 面试讲法

> 我这个项目里三个领域各有一份助手配置，某天打日志才发现 ssrm 那份漏了一个字段，
> 而引擎写的是 `spec.role_intro or "智能助手"`——默认值把配置缺失吃掉了，看起来一切正常，
> 实际领域人设从来没进过 prompt。这类 bug 的共性是：**兜底让错误变得安静**。
> 我的修法不是删兜底，而是把「领域包必须声明人设」变成一条单测，
> 顺带发现模板和变量都在说「会来问你」，拼起来重复了一遍，于是升了 prompt v2 并用版本机制回滚。
