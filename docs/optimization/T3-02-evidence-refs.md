# T3-02 证据校验换判据：从字面匹配到结构化引用（T3-5）

> 新增：`prompts/root_cause.v2.md`、`scripts/calibrate_evidence_refs.py`
> 改动：`app/agents/evidence.py`、`app/agents/classifier.py`、`app/prompts.py`、`app/config.py`、`app/evaluation/eval.py`、`frontend/src/pages/Playground.jsx`、`Makefile`
> 前置：T3-1 / T3-2（没有版本化与回归集，换判据无法证明"没变差"）

## 1. 问题：T0-03 的判据有分数反转

T0-03 的证据门禁是字面匹配——把 `evidence` 里的锚点拿去输入原文里找，算加权召回率。
它抓得住凭空编造（编造样本全 0.000），但实测出一组反转：

| 样本 | evidence | 字面分 |
|---|---|---|
| J | `EA_TIMEOUT / 504`（只丢两个错误码） | **1.000** |
| A | `error_code=EA_TIMEOUT 且 http_status=504，重试 4 次均失败，指向 EA 侧超时` | **0.684** |

**说得越少，分数越高。** 三个结构性原因（T0-03 §4.1 有算术拆解）：

1. **字段名是英文，证据是中文**：`retry_count: 4` 与「重试 4 次」语义一致、字面零重合
2. **分母是证据自身的词数**：说得越详细，未命中的中文 2-gram 越多，分数被稀释
3. **编码锚点太少压不住中文 gram**：4 个编码锚点（×3=12 分）压不住 7 个中文 gram

这三条都不是调权重能解决的：权重调高只会让"半编造"更松，不能让中文措辞命中英文字段名。
它测的是**引用密度**，不是**证据质量**——这个指标被用错了位置。

## 2. 判断：换判据，而不是把代理指标调准

真正的修法是把输出从「一段话」改成「引用列表」，让校验退化成两步：**字段存在吗？值相等吗？**

```json
{"root_cause_class": "ea_sync_timeout", "confidence": 0.97,
 "evidence_refs": [{"field": "error_code", "value": "EA_TIMEOUT"},
                   {"field": "http_status", "value": 504},
                   {"field": "retry_count", "value": 4}],
 "evidence": "EA 侧同步超时，重试 4 次仍失败", "suggested_action": "..."}
```

得分 = 有效引用 / 总引用。与文本长短无关，与措辞无关，且每条引用都能点开对应字段核对。

**为什么不能一步到位删掉字面匹配**：schema 是请求，不是保证。小模型可能不吐 `evidence_refs`，
这时不能因为「没按格式来」判它无据——那是把格式合规当成事实真伪。
所以保留 T0-03 的判据做兜底，两条路都有明确的触发条件（见 §4）。

## 3. 方案取舍

| 决策点 | 选择 | 为什么 |
|---|---|---|
| 判据 | 字段存在 + 值相等 | 零歧义、可人工复核、不额外调 LLM。代价是模型必须按 schema 输出，故保留兜底 |
| 值比较 | 数字按数值、字符串归一化、**长文本允许被引用为子串** | `504` 与 `"504"` 是同一事实；`EA_TIMEOUT` 与 `ea_timeout` 是同一事实；引用 `error_message` 时截断是合理的，但**改写不行**（子串关系保证引用的字都在原文里） |
| 字段路径 | 支持 `a.b.0.c` | 领域包里的 incident 是嵌套结构；不支持下标，合法引用会被误判成「字段不存在」 |
| 「少说少错」漏洞 | 加**引用条数下限**（`min_evidence_refs=2`），不压分 | J 只引 1 条也是 1.000。压分是伪造精度；加一个独立条件才诚实——「一条引用不足以支撑结论」是**规则**，不是**算术** |
| schema 说明放哪 | `index.json` 的 `post_example`，追加在 few-shot **之后** | 领域包的 few-shot 是领域知识（覆盖易混淆对），输出 schema 属于 prompt 版本；大模型对齐最后看到的格式，写在示例前会被老 schema 盖过去 |
| 兜底判据的阈值 | 不变（0.35） | 兜底只为"老模型不掉功能"，不是主判据，没有理由跟着改 |
| 新阈值 | 0.7（占比）+ 2（条数） | 结构化引用下诚实样本全 1.000、纯编造全 0.000，中间是空的——阈值落在哪里不敏感，宁紧勿松 |

## 4. 改动

### `app/agents/evidence.py`

```python
check_refs(refs, incident) -> list[dict]   # 逐条明细：field / value / ok / actual / reason
refs_score(detail)        -> float | None  # 有效/总数；无可用引用返回 None（=用不上，不是 0 分）
```

`None` 而不是 `0.0` 是关键：`0.0` 会把「模型没按 schema 输出」误判成「编造」。

### `app/agents/classifier.py::_apply_evidence_gate`

```
evidence_refs 可用 → refs 判据（占比 ≥0.7 且条数 ≥2）
evidence_refs 缺失 → 字面匹配兜底（原 T0-03 行为，一字未改）
两条都拦 → 压 confidence 到 0.4 + warning + needs_human_review
```

refs 模式下额外记 `evidence_literal_score`——线上可以对比两个判据的分歧率，
作为「能不能彻底删掉字面匹配」的数据依据，而不是靠猜。

### `prompts/root_cause.v2.md` + `index.json`

正文规则 3 改成「evidence_refs：2~4 项，field 必须真实存在、value 必须原样照抄」；
`post_example` 给一条完整形态示例。v1 保留，`--prompt-version=v1` 可原样回退做 A/B。

### 前端

`/classify` 返回的 `evidence_refs` 带 `ok` 与 `actual`，Playground 渲染成引用条：
对得上的绿底、对不上的红底并显示「输入实际值」。**校验在前端不做第二遍**——
落两份是必然事故。

## 5. 验收

### 5.1 标定（`make calibrate`，纯本地不调 LLM）

| 样本 | 类型 | score | 条数 | 门禁 |
|---|---|---|---|---|
| A | 诚实-引用三个编码字段 | 1.000 | 3 | 放行 |
| B | 诚实-无错误码，引流程字段 | 1.000 | 3 | 放行 |
| E | 诚实-引用状态码 | 1.000 | 2 | 放行 |
| J | 诚实但只引一条（原反转源） | 1.000 | 1 | **拦截（条数下限）** |
| G | 半编造-引真码、结论过度 | 1.000 | 2 | 放行 ⚠️ 见边界 |
| H / C / D / F / I / K | 纯编造（泛化/空话/套模板/换话题/换领域） | 0.000 | 2 | 拦截 |
| X | 字段真实但值被改 | 0.000 | 2 | 拦截 |

**诚实样本最低 1.000（v1 口径下最低 0.476）；纯编造全部 0.000。**
J 的分数仍是 1.000，但它被条数下限拦下了 —— 反转不是靠压分消除的，是靠加了一个独立条件。

### 5.2 v1 vs v2（同一批样本，`--record` 归档到 `prompts/scores.json`）

| 口径 | v1（字面匹配） | v2（结构化引用） |
|---|---|---|
| 回归集准确率 | 19/20 = 95% | 19/20 = 95% |
| 困难集准确率 | 25/25 = 100% | 24/25 = 96% |
| refs 采用率 | — | **100%**（20/20、25/25 全部按 schema 输出） |
| 平均引用条数 | — | 回归 3.1 / 困难 2.5 |
| 回归集被门禁拦下 | **3 条（全是诚实样本）** | **0 条** |
| 困难集被门禁拦下 | 0 条 | 1 条（HARD-018） |
| 证据探针 REG-05（详述） | 0.500 | **1.000** |
| 证据探针 REG-06（极简） | 0.684 | **1.000** |

**最有说服力的一行是「回归集被门禁拦下」**：v1 在 20 条手工样本上误杀了 3 条诚实判断
（REG-01 0.273、REG-03 0.091、REG-16 0.250 —— 全是口语化/无错误码的问法，正是字面匹配的死角），
v2 零误杀。误杀的代价是「正确答案被压到 0.4 转人工」，这是字面判据的真实成本，不是理论担心。

反转也消失了：REG-05（详述）0.500 vs REG-06（极简）0.684 → v2 下两者都是 1.000。

### 5.3 两条"下降"的诚实说明

**困难集 24/25（v1 是 25/25）**，掉的是 HARD-000（页面显示审批中、后台已通过 → 应为回调丢失，
v2 判成重复提交）。做了因子实验排除「schema 改动是元凶」：

| 配置 | HARD-000 判定（各跑 2 次） |
|---|---|
| v1 正文、无示例 | `xflow_callback_lost` ×2 ✅ |
| v1 正文 + v2 示例 | `duplicate_submit` ×2 |
| v2 正文、无示例 | `duplicate_submit` ×2 |
| v2 正文 + v2 示例 | `duplicate_submit` ×2 |
| v1 正文 + **52 字中性填充**（语义无关，只撑长度） | `duplicate_submit` ×2 |

中性填充也能翻，且 provider 前后同为 zhipu —— 这条样本本来就在判定边界上，**任何扰动都会翻**，
不是 v2 引入的系统性缺陷。顺带也验证了 T3-01 里的边界：25 条样本上的 ±1 差异，与模型抖动无法区分。

**困难集拦下 HARD-018**：模型只引 1 条（英文 `error_message`），分数 1.000 但被条数下限拦下，
置信度压到 0.4 转人工。这是 `min_evidence_refs=2` 的已知代价：**拦住诚实样本只多一次人工确认，
放进编造样本才是真风险**。要降低这个代价，正确做法是让模型在字段少时也拆出 2 条
（`source_system`、`downstream` 都是有效引用），而不是把条数下限调回 1 —— 那会把 J 的漏洞重新打开。

## 6. 边界（被追问时主动说）

1. **抓不到「引用正确、结论过度」**。样本 G 引真错误码，结论跳到「EA 服务整体不可用」，1.000 放行。
   这是蕴含判断（faithfulness），需要 NLI 小模型或人工标注集，两条判据都无能为力。
2. **条数下限会拦下「一条引用就够」的简单样本**（HARD-018 实证）。代价已量化：多一次人工确认。
3. **阈值仍不是统计标定**。12 条样本 + 45 条评测样本只能证明方向，画不出 P/R 曲线。
   真实做法要等真实流量的人工标注集。
4. **schema 合规性依赖模型能力**。这次三个 provider 上采用率 100%，换更小的模型可能掉；
   掉了不报错、只是静默回退字面判据 —— `evidence_mode` 字段就是为让这件事可见而存在的。
5. **值比较不判语义**。`retry_count: 4` 与 `"4"` 相等，但「重试四次」与 4 的等价关系不在校验范围内。

## 7. 面试讲法（90 秒）

> 我们的分类结果带一段"判断依据"，最初我用字面匹配校验它：把理由里的错误码、数字、词片段
> 拿去输入原文里找，算加权召回率。它抓得住凭空编造，但我发现一个反转 —— 只丢两个错误码的
> 证据得 1.000，引了四个字段还讲通顺的只得 0.684。说得越少分越高。
>
> 拆开算就明白了：输入是结构化 JSON，字段名是英文 `retry_count`，模型用中文说「重试 4 次」，
> 语义全对、字面零重合；而分母是证据自己的词数，说得越详细被稀释得越厉害。
> 这三条都不是调权重能解决的，因为这个指标测的是**引用密度**，不是**证据质量**。
>
> 所以我换了判据：要求模型输出结构化引用，`field` + `value`，校验退化成「字段存在吗、值相等吗」。
> 分数跟文本长短彻底无关。同时保留字面匹配做兜底 —— 模型不按 schema 输出时不能因为"格式不对"
> 就判它无据，那是把格式合规当成事实真伪。
>
> 还有一个坑：只引一条正确字段也能拿 1.0，等于奖励少说少错。我没有去压分（那是伪造精度），
> 而是加了一个独立条件：引用条数下限 2 条。「一条引用不足以支撑结论」是规则，不是算术。
>
> 换判据必须配回归集才能证明没变差。实测 20 条手工回归集上，老判据把 3 条诚实判断误杀成无据，
> 新判据零误杀 —— 这个数字比准确率更能说明问题，因为门禁误杀的代价是正确答案被转人工。
