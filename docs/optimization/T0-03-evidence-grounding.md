# T0-03 证据可回溯校验（白盒门禁）

> 新增：`app/evidence.py`　接入：`app/classifier.py::_apply_evidence_gate`
> 类型：可信度机制（把「模型的自我保证」换成「可验证的事实」）
>
> **状态更新（T3-5 之后）**：本文描述的字面匹配已降为**兜底判据**，只在模型不按
> `evidence_refs` schema 输出时生效；主判据换成结构化引用，见
> [`T3-02-evidence-refs.md`](T3-02-evidence-refs.md)。本文保留的原因：它记录了换判据的动因
> （§4.1 的算术拆解、§4.2 的分数反转）—— 那些是"为什么不能只调权重"的证据，删了就只剩结论。

## 1. 问题

分类结果里有 `evidence` 字段，要求模型「引用输入中的具体字段和值作为依据」。
但代码只校验了 `root_cause_class` 是不是合法枚举，**没有任何一行代码检查 evidence 是否真的来自输入**。

这带来一个很难察觉的失效模式：模型可以给出一个高置信度、理由通顺、但**完全编造**的判断，
系统一路放行。比如输入里只有 `EA_TIMEOUT`，模型说「数据库连接池耗尽」，
置信度 0.95 —— 前端会显示「✅ 达到自动处置门禁」，值班同学照着去重启数据库。

而 `confidence` 是模型自报的，它和「判断是否正确」之间没有任何强制关系。越会编的模型越敢给高分。

## 2. 判断：要一层「能和输入对账」的检查

候选方案：

| 方案 | 成本 | 可解释 | 问题 |
|---|---|---|---|
| A. 让模型再自评一次（LLM-as-judge） | 每次 +1 次调用，延迟翻倍 | 差 | 同一个模型，同样会说谎；判断过程不可审计 |
| B. 要求模型输出证据的**字符下标** | 0 | 好 | 模型给不出准确下标，幻觉率更高 |
| **C. 把 evidence 的锚点拿去输入里找** | 0（本地字符串比对） | **好：每条都能人工复核** | 同义改写会漏判 |

选 C。理由不是它最准，是它**白盒**：任何一条「无据」判定，都能把两段文本摆在一起给人看；
而 A 的结论永远只是「另一个模型觉得不行」。

这一层的定位必须说清楚：**它是门禁，不是裁判**。

- 分数低 → 压置信度、强制人工（宁可不答，不可错答）
- 分数高 → 只证明「理由引用的是真实输入」，**不证明结论正确**

## 3. 算法

```
evidence ──┬─→ ASCII 锚点（错误码/单号/状态码/字段名），权重 3
           └─→ 中文 2-gram（去停用词），权重 1
                      ↓
        加权召回率 = Σ(命中锚点权重) / Σ(全部锚点权重)
```

三个细节：

1. **编码类锚点权重 3 倍**。`EA_TIMEOUT`、`FT20261025088`、`504` 这类字符串出现在输入里
   几乎不可能是巧合，而中文词片段天然容易命中（「问题」「异常」到处都是）。
2. **输入池包含 key 而不只是 value**。evidence 里写 `http_status=504` 属于有效引用，
   所以 `_flatten()` 把 incident 的键名也摊进池子。
3. **锚点太少不做统计**。只有 1~2 个锚点时（典型是「EA_TIMEOUT / 504」这种极简引用），
   全中记 1.0、否则记 0.0 —— 用比例算没有意义，但「全中」本身就是强证据。

## 4. 阈值怎么来的：10 条手工标定样本

| # | 类型 | evidence | score |
|---|---|---|---|
| A | 诚实 + 引用错误码 | `error_code=EA_TIMEOUT 且 http_status=504，重试 4 次均失败，指向 EA 侧超时` | **0.684** |
| B | 诚实 + 同义改写 | `审批单已通过但 SSRM 侧没有对应注册任务，说明回调未到达` | **0.476** |
| E | 诚实 + 引用状态码 | `http_status=409 且提示申请已存在，判定为重复提交` | **0.684** |
| J | 诚实 + 极简引用 | `EA_TIMEOUT / 504` | **1.000** |
| G | 半编造（借真码讲通用结论） | `error_code=EA_TIMEOUT，说明 EA 服务整体不可用，建议联系 EA 团队` | 0.400 |
| H | 半编造（通用词） | `网络抖动导致调用超时，建议直接重试` | 0.167 |
| C | 纯编造（泛化） | `看起来是网络问题导致供应商数据同步异常` | 0.000 |
| D | 纯编造（泛化） | `系统整体负载较高，可能是数据库连接池耗尽` | 0.000 |
| F | 纯编造（空话） | `根据经验判断，这是一个已知问题，按标准流程处理即可` | 0.000 |
| I | 纯编造（套模板） | `根据历史经验，此类问题多为下游系统不稳定，建议转人工处理` | 0.000 |
| K | 编造（换话题） | `供应商资质审核不通过，需要补充营业执照` | 0.000 |

阈值取 **0.35**（`settings.min_evidence_score`），落在「半编造 0.167」与「诚实最低 0.476」之间：

- 诚实样本最低 0.476，留 0.126 余量 —— 宁可漏放，不可错杀（错杀 = 正确答案被转人工）
- 纯编造全部 0.000，任何阈值都能拦住
- 半编造 G（0.400）**会通过**，这是这层能力边界，见下

### 4.1 为什么诚实证据最高只有 0.684（算术拆解）

得分 = Σ(命中锚点权重) / Σ(全部锚点权重)，编码类权重 3、中文 2-gram 权重 1。逐个拆开：

| 样本 | 编码锚点 | 中文 2-gram | 算式 | 得分 |
|---|---|---|---|---|
| A | 4/4（4×3=12） | 1/7 | (12+1) / (12+7) | 0.684 |
| B | 1/1（1×3=3） | 7/18 | (3+7) / (3+18) | 0.476 |
| E | 2/2（2×3=6） | 7/13 | (6+7) / (6+13) | 0.684 |
| J | 2/2（2×3=6） | 0/0 | 锚点不足 3 个且全中 | 1.000 |
| G | 2/2（2×3=6） | 0/9 | 6 / (6+9) | 0.400 |

**A 的 0.684 是这么来的**：编码锚点 4 个全中（12 分），中文 2-gram 7 个只中 1 个（「超时」，1 分），
13/19 = 0.684。丢掉的 6 个是「重试 / 次均 / 均失 / 失败 / 指向 / 侧超」——
问题不在证据编造，而在**输入是结构化 JSON**：`retry_count: 4` 的字段名是英文，
模型用中文说「重试 4 次」，语义完全正确，字面上一个字符都不重合。

三个结构性原因叠加，决定了诚实样本的上限：

1. **字段名是英文，证据是中文**。中文锚点只能靠 `error_message` 里的原文命中
   （A 里就一个「超时」）。输入越结构化，中文命中率越低。
2. **分母是「证据自己的词数」**。说得越详细，中文 2-gram 越多，未命中的也越多 —— 分数被稀释。
3. **编码锚点数量太少**（4 个 ×3 = 12，压不住 7 个中文 gram）。权重调高只会让 G 更松，不解决 1。

### 4.2 这个指标测的是什么、不测什么

测的是**引用密度**：这段理由有多少字能在输入原文里检索到。

不测：证据是否充分、结论是否正确、是否从证据过度推断。

由此产生一个必须承认的反转：

```
J（只丢两个错误码）      = 1.000
A（引了四个字段 + 通顺解释）= 0.684
```

**说得越少，分数越高。** 这说明它不能当「证据质量分」用，只能当「有没有据」的判据。
0.35 这个阈值的作用也只是二分：`0.000~0.167`（无据）vs `0.400+`（有据），
中间那段不是「中等质量」，是「模型改写幅度较大」。

所以它不该被用来排序、不该展示给用户当可信度打分，只该做一件事：
**在完全没有据的时候把 confidence 压下去。**

### 4.3 真正的修法：结构化引用

自由文本匹配是代理指标，换掉它才是根治。把输出 schema 从「一段话」改成「引用列表」：

```json
{
  "root_cause_class": "ea_sync_timeout",
  "confidence": 0.95,
  "evidence_refs": [
    {"field": "error_code", "value": "EA_TIMEOUT"},
    {"field": "http_status", "value": "504"},
    {"field": "retry_count", "value": "4"}
  ],
  "evidence": "EA 侧同步超时，重试 4 次仍失败",
  "suggested_action": "..."
}
```

校验退化成两步，零歧义：**字段存在吗？值相等吗？** 得分 = 有效引用数 / 总引用数。

- 详细与简洁不再影响分数（不惩罚长度）
- 同义改写问题消失（校验的是字段和值，不是措辞）
- 可审计性更强：每条引用都能点开对应字段

代价：要改 system prompt、FEW_SHOT、`_validate` 与前端渲染，且老模型可能不按 schema 输出
（需保留 `evidence` 自由文本作为兜底，`evidence_refs` 缺失时退回当前的字面匹配）。

归属：**T3（prompt 版本化 + 回归）**，因为 schema 变更必须配回归集，否则改完无法证明没变差。
在此之前，当前实现按「只做无据拦截」的定位使用，不要对外宣称它能评估证据质量。

## 5. 门禁动作

```python
score = evidence_score(result["evidence"], incident)
if score < settings.min_evidence_score:
    result["confidence"] = min(result["confidence"], settings.low_evidence_confidence_cap)  # 0.4
    result["evidence_warning"] = "判断依据未能回溯到输入原文，已压置信度并建议人工复核"
result["needs_human_review"] = result["confidence"] < settings.min_confidence_for_auto_action
```

两个决定：

- **压到 0.4 而不是直接丢弃结论**。结论本身可能是对的，只是理由没引对；转人工比丢结果更有用，
  而且 0.4 一定低于 0.85 门禁，人工复核这一步跑不掉。
- **只作用于 LLM 通道**。规则通道的 evidence 是代码用结构化字段拼的（「命中幂等冲突特征」），
  不存在编造风险；套用同一个匹配器只会把正确的规则判断误伤成低置信 —— 实测规则通道
  在 `EA_TIMEOUT` 用例上 confidence=0.8，如果过门禁会被压到 0.4。

## 7. 边界（被追问时主动说）

1. **同义改写会漏判**。模型说「审批早已完成」而输入是「状态 APPROVED」，字面不重合 → 0 分。
   这是字面匹配的固有代价，方向是「误判为无据 → 转人工」，不是「误判为有据 → 放行」。
2. **抓不住「引用正确但结论过度」**。样本 G 就是：引了真错误码，结论跳到「EA 服务整体不可用」，
   得分 0.400，能过门禁。这类问题属于 faithfulness / 蕴含判断，需要另做（评测集或 NLI 小模型）。
3. **中文 2-gram 天然命中**。已用停用词表压掉「问题」「异常」「因为」这类词，但压不干净；
   输入越长分数越容易虚高。
4. **阈值是在 10 条自造样本上标定的**。样本量太小，只能说「方向对」，不能说「校准好了」。
   真实做法是拿一批人工标注的 (incident, evidence) 对，画 precision/recall 曲线再定阈值 ——
   这一步依赖真实数据，等 T4 的标注集一起做。

## 8. 面试讲法（60 秒）

> 置信度是模型自报的，这句话本身没有信息量 —— 越会编的模型越敢给 0.95。
> 所以我加了一层不依赖模型的检查：把 evidence 里的锚点（错误码、单号、中文词片段）
> 逐个拿去输入原文里找，算加权召回率。编码类锚点权重高，因为它几乎不可能被顺手编对。
>
> 分数低于阈值就把置信度压到 0.4，强制转人工。注意这个动作是「降权」不是「否决」——
> 结论可能是对的，只是理由没引对，人的判断比丢掉结果有价值。
>
> 它的价值在于白盒：任何一条「无据」判定，我都能把两段文本摆出来让人复核。
> 对比之下，用 LLM 再判一次既贵一倍，又不可审计。
>
> 边界我也清楚：它只能抓「凭空编造」，抓不到「引用正确但结论过度」，也不能处理同义改写。
> 所以它是第一层防线，不是唯一一层 —— **如果只能留一层，我留这层，因为它零成本且可解释**。

**如果被追问「为什么诚实证据只有 0.68，不是 0.9」**（这题问的是你懂不懂自己的指标）：

> 因为输入是结构化 JSON，字段名是英文的 `retry_count`，模型用中文说「重试 4 次」，
> 语义对、字面不重合，所以中文锚点基本全丢。这一版的分数本质是「引用密度」，
> 不是「证据质量」—— 甚至有个反转：只丢两个错误码的证据得 1.0，引了四个字段还讲通顺的只得 0.68。
>
> 所以我不敢把它当质量分用，只用它做一个二分判断：完全没有据的时候把置信度压下去。
> 真要解决，得把自由文本换成结构化引用 —— 让模型输出 `{field, value}` 列表，
> 校验退化成「字段存在吗、值相等吗」，同义改写和长度惩罚两个问题一起消失。这个改动要配回归集，我排在后面做。
